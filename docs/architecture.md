# 架构

## 进程与边界

React 渲染进程 → 受限 preload API → Electron 主进程 → `LanNode`。

渲染进程没有 Node 权限，启用 `sandbox`、`contextIsolation` 和 `webSecurity`。主进程只接受自己的顶层窗口 IPC，校验参数，通过原生文件对话框或拖放授权获得文件路径。附件使用随机的临时 token，界面不能直接提交一个路径给发送接口。

生产界面由 `nearlink://app/` 提供，图片由只接受已登记附件 ID 的 `nearlink-media://file/` 提供。未授予页面网络、远程导航、弹窗、iframe 或任意本地文件读取权限。消息按纯文本渲染。

## 局域网发现

- UDP `45875`，组播 `239.255.43.21` 和各 IPv4 网卡的子网广播。
- 每 3.5 秒公告协议版本、设备 ID 和实际 HTTPS 端口。公告不包含昵称、头像或消息。
- 默认 HTTPS `45876`；端口占用时选择空闲端口并通过发现公告。
- 双向 hello 交换资料。每个请求携带客户端证书，应用验证证书指纹与资料中的设备 ID 一致。
- 发现故障不影响「IPv4:端口」手动连接。群邀请包含成员端点提示，成员之间仍需用对应证书建立直连。

## 消息

`POST /v1/hello`：协议版本、资料、端口。

`POST /v1/events`：群邀请或消息。消息包含 UUID、会话信息、发送者、纯文本和附件描述。私聊 ID 从排序后的两台设备指纹确定；群聊使用随机 UUID，固定成员列表。

发送事务同时写入 `messages` 和逐接收者的 `deliveries`。对方 SQLite 落盘后返回确认；发送方标记送达。失败保留在队列，每次成功 hello 后顺序重试。`inbox` 记录事件摘要，使重复投递幂等，并拒绝同一事件 ID 的不同内容。群邀请排在群主的第一条消息之前。送达表示对方数据库收到，区别于已读。

本机消息使用自增序号排序和分页，避免设备时钟差导致翻页遗漏。远端时间仅用于显示。搜索在 SQLite 中按参数化子串匹配执行，支持中文，最多返回 60 项。每次历史查询默认 100 条。

## 文件

附件描述只包含 UUID、安全文件名、64 位安全整数大小、MIME 和 SHA-256，不包含发送方路径。发送前按 256 KB 读块流式计算摘要，按顺序准备多个附件，避免内存和磁盘突发。

`GET /v1/files/:id`：必须提供有效客户端证书、属于原消息的会话，并使用不超过 4 MB 的单个 HTTP Range。只会提供用户已分享的原文件。发送方检查文件仍存在且大小一致。

接收方每次读取 4 MB 区间，流式追加到本地 `.part`。暂停中止当前请求，继续时以文件实际大小作为偏移；重启后传输转为暂停。最终流式计算 SHA-256，通过后原子重命名并保存完成状态；失败删除错误的 partial，从 0 重试。空文件走同一校验流程。

`POST /v1/files/:id/receipt`：经认证的接收者报告进度和校验完成状态。每个接收者独立记录，已完成的确认不会被迟到的进度包覆盖。普通文件手动接收；允许类型且不超过 10 MB 的图片自动接收。最多同时进行 3 个接收任务。

## 存储

Node 内置 `node:sqlite`，WAL、外键、参数绑定、显式事务。表：`meta`、`peers`、`conversations`、`messages`、`deliveries`、`inbox`、`transfers`、`receipts`。模式版本 `PRAGMA user_version=1`。

SQLite 保存元数据；附件留在文件系统。数据目录独立于安装目录，升级应用不删除聊天。退出托盘应用后可备份整个目录。
