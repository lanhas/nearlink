# 安全模型

邻线面向可信局域网，采用免登录和首次接触自动信任的方式。

- 每台设备生成持久化 RSA 证书。设备 ID 是证书的 SHA-256 指纹，昵称与设备名变化不改变身份。
- TLS 传输同时使用客户端证书。没有公共 CA；应用自己核对证书指纹，绝不是简单关闭证书验证后不再检查。
- 首次手动连接信任当次 TLS 连接看到的证书。自动发现使用公告中的指纹连接，并核对实际证书。
- 首次连接前没有外部身份根；攻击者如果控制首次发现/首次连接，仍可能冒充新设备。两台设备核对完整指纹可验证是否连到预期设备。当前没有强制配对码或人工批准流程。
- 同一局域网中运行邻线的其他设备可以被发现、介绍自己或向你发起新会话；不应在不可信的公共 Wi-Fi 上使用免配对模式。
- 既有会话不允许远端任意变更成员。消息发送者必须与客户端证书一致，文件请求者必须是原会话成员。未知设备不能读取历史；没有网络历史导出端点。
- 文件名去除路径、Windows 保留名和危险字符，并限制 UTF-8 长度；接收目录由应用决定。不会执行收到的文件，文件操作只显示所在文件夹或另存为。
- 请求体上限 2 MB，Range 上限 4 MB，同时接收上限 3；消息和资料有长度限制，页面禁止远程脚本、远程导航和弹窗。
- 数据不上传服务器，没有遥测、登录或云端备份。运行时不检查互联网更新。

设备文件和 SQLite 在本地不额外加密。拥有本机账户/磁盘读取权限的人可以读取这些数据。证书私钥在 `identity.json` 中，数据目录在 macOS 使用私有目录权限；Windows 依赖用户目录的系统访问控制。

请勿把数据目录或私钥提交到公开 issue。如发现问题，先仅描述受影响版本与触发条件，避免上传聊天内容。
