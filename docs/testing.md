# 验证

## 自动化

`npm test` 使用真实 HTTPS/TLS 监听器、独立证书和 SQLite 数据库，覆盖：

1. 双向设备发现、证书指纹验证、伪造 hello、拒绝公网地址。
2. Unicode/多行文本、纯文本保存、未读、送达确认、事件去重、冲突拒绝和中文搜索。
3. 三节点群邀请、成员端点交换和任意成员的群消息发送。
4. 伪造消息发送者、修改既有群成员信息、未知设备发消息的拒绝。
5. 接收设备关闭与重启后的离线队列补发、身份持久化。
6. 48 MB 文件真实传输，途中暂停，重启接收节点，按实际偏移续传，摘要一致，逐接收者确认，越权/无效 Range 拒绝。
7. 空文件、Windows 保留文件名、路径穿越、中文超长文件名和内容篡改后的校验失败。
8. 资料、105 条本地记录、100 条分页、SQLite integrity_check。
9. 4 GiB 以上字节偏移的实际 Range 读取（稀疏文件，非完整传输；Windows CI 跳过以避免分配大文件）。
10. 真实 UDP 组播/广播自动发现两个 TLS 节点。CI 网络环境跳过这项，在本地运行。

`npm run smoke` 启动真实 Electron 应用与两个真实通信节点，通过 UI 验证资料、纯文本与隔离、群聊、图片接收预览、文件接收、搜索跳转、设备、传输和深色外观，以及原生文件选择/剪贴板图片粘贴。所有数据写入被 Git 忽略的 `.smoke/` 隔离目录。成功后生成测试报告和项目截图，应用正常使用不包含测试数据。

使用 `NEARLINK_EXECUTABLE=/path/to/Nearlink.app/Contents/MacOS/Nearlink npm run smoke` 可测试已打包的 macOS 应用；Windows 指向解包后的 `Nearlink.exe`。

## 验证边界

测试节点运行在同一主机上的真实网络端点；这不等于已经在用户的实体 Mac、Windows、路由器和防火墙之间完成互通测试。Windows 原生构建和 GUI 测试由 GitHub Actions 的 Windows runner 执行，macOS 由 Mac runner 执行。

发布后建议在真实设备检查首次网络权限、自动发现、手动连接与所需大小的文件传输。跨公网、IPv6、多网段路由、用户路由器的 AP 隔离不在首版保证范围内。文件使用 JS 安全整数与 HTTP 字节区间，没有 2 GB 的实现上限；本次完整文件自动化样本是 48 MB。
